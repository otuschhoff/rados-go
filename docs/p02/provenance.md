# P02 Provenance and Reproduction

The implementation is based on protocol facts from Ceph `v20.2.0` commit
`69f84cc2651aa259a15bc192ddaabd3baba07489`. The repository-wide source and
licensing decisions remain in `docs/p00/protocol-sources.md` and
`docs/p00/licensing.md`.

## Source-Derived Independent Oracle

The five files under `testdata/p02` cover the revision-1 banner, one- and
four-segment CRC frames, and one- and multi-record secure frames. Each strict
sidecar records the source commit and paths, fixture SHA-256, pinned image,
generator identity, synthetic-secret status, and applicable license notices.
`tools/p02-verify` hash-binds the oracle source and Dockerfile and validates the
complete artifact set.

`integration/p02/oracle.cc` is an independent C++/OpenSSL byte generator. Its
only secure-frame secret is the deterministic byte sequence 0 through 63; it
is test material, not a credential. Exact Go parity is exercised by
`TestP02BannerFixture`, `TestP02CRCFixtures`, and `TestP02SecureFixtures`.
The manifest `kind` remains `native-oracle` to identify the C++ generator, but
the generator implements protocol behavior derived from pinned source. It does
not link to or invoke Ceph's `FrameAssembler`.

The generated bytes are distributable fixture outputs rather than copied Ceph
source text, but their provenance is intentionally conservative. Banner bytes
cite `LGPL-2.1-or-later`. CRC and secure fixtures also derive CRC behavior from
BSD-3-Clause `src/common/sctp_crc32.c`, so they use
`(LGPL-2.1-or-later AND BSD-3-Clause)`. Redistributors must retain the
corresponding LGPL and, where applicable, BSD-3-Clause notices. No legal-review
approval or named reviewer is asserted by the manifests.

Run `make reproduce-p02` to build the oracle in the digest-pinned Ceph image,
regenerate all five files in a temporary directory, byte-compare them, and
reject extra output.

## Current Reproduction Truth

As of 2026-09-14, the independent oracle compiled locally with Apple clang 21
and OpenSSL 3.6.4. The digest-pinned Docker reproduction was attempted, but its
package download/build was canceled. It remains **pending** until
`make reproduce-p02` is rerun to completion. Local compilation does not replace
the pinned-container reproduction gate.

The image, compiler, Ceph packages, and downloaded Ceph RPMs are pinned. The
Dockerfile currently resolves `openssl-devel` from the image's enabled
repositories because no verified OpenSSL development-package NEVRA and RPM
checksum were recorded before the build was canceled. An exact package value
must not be guessed; this unresolved dependency is another reason the Docker
reproduction is not a completed evidence gate.

Actual vectors produced by executing upstream Ceph `FrameAssembler` remain an
unresolved gate. P02 cannot be declared complete solely from the current
source-derived independent fixtures, even after their local or containerized
reproduction succeeds.
