# P07 Mutation Path Evidence

The qualification server is Ceph v20.2.4 commit `7f793731f1b39eb4f465e960113d2363c311b964`, anchored to architecture-specific content-addressed images and pinned `ceph-mon`, `ceph-osd`, and `librados.so.2` identities enforced by `tools/p07-verify`.

`integration/p07/reproduce.sh` provisions a fresh three-OSD BlueStore cluster, uses 8 GiB OSD block devices, creates the replicated `p07-data` pool (size=2, min_size=1), and drives both Go and native mutation workflows. The probe validates create/exclusive admission, ordered write/write-full/append/zero/truncate completion semantics, remove/missing behavior, flush and shutdown. For deterministic recovery evidence, the harness pauses the acting primary, starts an append over the established session, proves the call remains incomplete, then kills and marks down that primary; the append must recover through the remap and native librados must observe exactly one appended byte.

The mutation and completion grounding is pinned to Ceph source paths relevant to operation flags, request identity, replay handling, and completion ordering: `src/messages/MOSDOp.h` (operation and flag envelope), `src/osd/osd_types.h` and `src/osd/osd_types.cc` (`reqid` and `client_inc` semantics), and `src/osdc/Objecter.cc` (request submission, replay, completion, and remap behavior). In the v8 envelope, zero explicit request-name and request-TID fields intentionally select `MOSDOp::get_reqid()` fallback identity: the authenticated original source name, request incarnation, and stable messenger header TID. Ceph records that derived `osd_reqid_t` for duplicate detection, so retries retain the same header TID and incarnation.

Native interoperability is independently implemented from the Go client path. `integration/p07/native_driver.c` and `integration/p07/native_benchmark.c` bind `librados.so.2` dynamically through `dlopen`/`dlsym`, isolating the native dynamic ABI from compile-time headers and from the Go transport implementation.

Benchmark methodology is fixed and bounded: sizes `[4096, 65536, 1048576, 4194304]`, concurrency `[1, 16, 64]`, workloads `read|write|mixed`, two operations per worker, and transports `secure|crc`, producing one run per implementation/transport combination and 36 rows per run. CPU time and Go allocation counters are deltas over the complete 36-row matrix after connection and pool setup. Native allocation count and byte totals are explicitly unavailable because the dynamically loaded librados ABI exposes no portable process-wide allocation counters; those report fields are `null`, while native CPU and resident-memory measurements remain recorded. `max_rss_bytes` is the operating system's full-process lifetime peak resident set size reported at the end of that benchmark process; it is not a delta and is not scoped to an individual row. The report also records the qualification kernel, CPU model and visible logical CPU count, cgroup CPU and memory limits, and Docker server version. The methodology records baseline measurements only and does not claim cross-implementation equivalence or portability; later allocation budgets cannot compare implementations without adding a qualified native allocator instrument.

The checked-in report excludes secrets: no CephX keys, connection secrets, ticket material, or object payloads are stored. Reproduction mounts ephemeral key files into the benchmark and probe containers instead of passing keys in process arguments, and Docker-managed ephemeral volumes are cleaned by the harness trap.
