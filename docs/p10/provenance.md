# P10 Snapshot and Specialized-I/O Evidence

The qualification server is Ceph v20.2.4 commit `7f793731f1b39eb4f465e960113d2363c311b964`. Architecture-specific content-addressed images and exact `ceph-mon`, `ceph-osd`, librados package, and `librados.so.2` hashes are pinned by `tools/p10-verify`.

`integration/p10/reproduce.sh` provisions FSID `21000000-2222-4333-8444-101010101010` on `172.30.110.0/24` with three 8 GiB sparse BlueStore OSD devices. It creates the size-two replicated pools `p10-named` and `p10-self` through `p10-replicated-rule`, and size-three/min-size-two `p10-ec` through the `jerasure` profile `p10-ec-profile` (`k=2`, `m=1`, failure domain `osd`) and `p10-ec-rule`. EC overwrites remain disabled so alignment and overwrite restrictions are observable. The runner waits for all PGs to become available and non-degraded before starting interoperability probes. `client.p10` receives monitor read/write access and OSD read/write/execute access restricted to those three pools.

The native driver resolves every librados entry point at runtime with `dlopen("librados.so.2")` and `dlsym`; its only link dependency requested by the build is `libdl`. Its seed phase creates, lists, looks up, names, timestamps, reads, rolls back, and removes a named snapshot. In the separate self-managed pool it allocates a snapshot, installs its write context, reads the immutable version, rolls back, and removes it. The post-Go phase reads a Go-created named snapshot and head, validates ordinary and copy-from2 results, validates an EC copy, and removes the handoff snapshot.

The Go probe exercises only current public APIs and emits one JSON value to stdout. It covers both snapshot models; `WriteSame`, `Checksum`, `SetAllocationHint`, `SparseRead`, `CopyFrom`, and `CopyFrom2`; and all three pool capability methods. `CopyFrom2` preserves pinned librados behavior: its independent copy-flags field is zero, while `truncateSequence` and `truncateSize` are encoded after the source object and locator in the operation input payload exactly as `ObjectOperation::copy_from2` does. The server uses that context when reading a source whose truncate sequence is older; it does not request destination truncation. The EC path checks aligned full-object write/read plus selected read-oriented operations, requires partial overwrite, writesame, and OMAP to report `ErrUnsupported`, and records the nonzero required alignment exactly.

`testdata/p10/crushmap.bin` is the binary CRUSH map captured from the same deterministic three-OSD topology. `mappings.txt` and `mappings-osd1-out.txt` are the complete `crushtool --test --show-mappings --rule 2 --num-rep 3 --min-x 0 --max-x 255` output for all devices in and for `--weight 1 0`, respectively. The fixture test requires exact parity for all 512 `CHOOSE_INDEP` mappings, including collision retries and override-weight filtering.

`CloneRange` is intentionally outside P10 evidence because no corresponding current entry exists in `docs/p00/api-inventory.csv`. The harness does not infer an inventory contract from the presence of a method and makes no clone-range qualification claim.

The report is assembled in the run's temporary directory and renamed into `docs/p10/integration-report.json` only after all assertions and identity captures succeed. Its artifact map includes every root and internal Go source/test file, all P10 integration source, schema, verifier source/tests, P10 documentation, module files, and the Makefile. The report itself is excluded to avoid a circular digest. No credentials or runtime payload files are retained.
